# Plan 08-01: Settings TLV / Delta Schema Migration

**Goal**: Implement compact Tag-Length-Value (TLV) flash serialization with 1024B buffer, backward-compatible lazy migration from v63 flat struct, unknown tag resilience, and full parity verification.

## Requirements
- `REQ-persistence-contract`: Dual ping-pong sectors, monotonic sequence arbitration, CRC32 integrity verification, brownout recovery.
- Non-destructive schema evolution: Future field additions don't wipe operator calibration.
- `SETTINGS_VERSION`: Bump to `64u` (TLV wire format).
- Zero data loss across upgrade from existing v63 flat struct.

## Success Criteria
1. `SETTINGS_FLASH_BUFFER_BYTES` expanded to 1024 bytes (4 flash pages).
2. Wire format uses `settings_header_t` (magic, version 64, seq, payload_len, reserved) + TLV record stream + trailer CRC32.
3. `settings_load()` parses TLV stream with strict boundary verification, skipping unknown tags safely.
4. Legacy v63 flat struct detection (`version == 63`) lazily unpacks into runtime globals without immediate flash overwrite.
5. `settings_save()` serializes current runtime globals into TLV format, verifies readback CRC, and alternates sectors.
6. `scripts/test_settings_parity.py` validates tag enum parity across `settings_save()`, `settings_load()`, and `settings_defaults()`.
7. `tests/host/test_persistence.c` covers fresh flash, ping-pong alternation, v63 migration, unknown tag skipping, and truncated buffer defense.
8. `ninja -C build_local`, `ninja -C build_sim`, and `python3 scripts/validate_regression.py` pass 100%.
